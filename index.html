Lesson 1: What is an IDN homograph?

Internationalized Domain Names (IDNs) allow Unicode characters to appear in domain names. An IDN homograph attack exploits visually confusable Unicode characters from scripts such as Cyrillic and Greek to imitate familiar Latin letters. The result can be a lookalike domain that appears nearly identical to a trusted hostname while remaining a different string underneath.

Aa

Unicode lookalikes

A Latin letter such as a may have visually similar characters in Cyrillic, Greek, fullwidth Latin, or other Unicode ranges.

xn

Punycode

DNS uses an ASCII-compatible representation for internationalized labels. Suspicious Unicode domains may therefore appear as an xn-- encoded hostname.

!

Visual deception

The danger comes from what a person sees. Two strings can look alike while containing different code points and resolving to different destinations.

Lesson 2: How the deception works

A homograph does not require changing the entire word. Replacing only one character may be enough to make a hostname look familiar at a glance.

1

Start with a familiar ASCII name

Example: paypal.com using ordinary Latin characters.

2

Replace a character with a visual lookalike

A Unicode character may resemble the original letter while having a different code point.

3

The hostname is no longer the same string

The browser or DNS layer may represent the internationalized label using Punycode.

4

A person may still read it as the trusted name

This is why character inspection and browser protections matter.

Lesson 4: Browser protections

IDN homographs are a real concept, but modern browsers do not simply display every internationalized hostname as Unicode. Suspicious combinations may be displayed in ASCII-compatible Punycode instead.

!

Important context

A visual example in this educational tool does not guarantee that Chrome, Firefox, Safari, Edge, or another browser will display the same hostname in Unicode. Browser display rules, script combinations, font rendering, and IDN policies all affect what a user actually sees.

Defensive checklist: what should you inspect?

These signals are more useful than relying only on whether a hostname “looks right.”

01

Non-ASCII characters

Check whether the hostname contains characters outside ordinary ASCII.

02

Mixed writing systems

A hostname combining Latin and Cyrillic or Greek characters deserves additional scrutiny.

03

Punycode representation

An xn-- label is a useful clue that the hostname contains internationalized characters.

Frequently asked questions

Does an IDN automatically mean a domain is malicious?

No. Internationalized domain names are legitimate and important for users of non-Latin writing systems. Risk comes from deceptive use, not from Unicode itself.

What is Punycode?

Punycode is an ASCII-compatible encoding used to represent Unicode domain labels in the DNS system. Internationalized labels commonly begin with xn--.

Why do some examples look identical on one device but different on another?

Fonts, operating systems, browsers, and script-rendering rules can change how similar two Unicode characters appear.
